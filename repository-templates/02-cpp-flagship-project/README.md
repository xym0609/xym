# C++ Flagship Project

这是未来主项目仓库的占位框架。当前尚未选定具体项目，也没有把任何功能标记为已实现。

## 选题原则
- 与目标岗位相关，能展示不止语法层面的能力。
- 规模可控，能逐步实现、测试、演示和维护。
- 能解释模块边界、数据流、错误处理和关键设计取舍。
- 尽量包含可复现构建、自动化测试、日志、配置和 CI。

## 候选方向

| 方向 | 主要能力证明 | 前置基础 |
|---|---|---|
| Linux TCP/HTTP 服务端 | 网络编程、并发、协议解析、性能与稳定性 | C++、Linux、网络基础、线程同步 |
| 线程池/任务调度器 | 线程生命周期、同步原语、任务队列、异常传播 | C++、并发基础 |
| 嵌入式数据采集 | 硬件接口、资源约束、可靠性、实时性 | C/C++、硬件平台、调试工具 |
| 小游戏/引擎模块 | 状态管理、模块设计、资源管理、交互逻辑 | C++、面向对象、图形/游戏框架 |

若以后选择 C++ 后端/系统方向，可以考虑 Linux 下的 TCP/HTTP 服务，把线程池、日志和配置作为其中的模块；不必为了显得高级而单独堆名词。不同方向不要同时开多个大项目，先根据目标岗位与现有基础选一个。
